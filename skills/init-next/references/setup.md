# Version selection and generation

Resolve versions on every invocation using npm metadata, official release notes and publisher image manifests. Select the newest mutually compatible stable releases published at least seven days ago. This applies to create-next-app, Node, pnpm, dependencies, aqua tools/registry and Actions; the target's pnpm policy does not protect the generator or other bootstrap tools automatically.

Use the current supported Node LTS, with matching Node type major. Match React/React DOM and Mantine core/hooks exactly. Check Next.js, React Compiler, TypeScript, Biome and next-intl compatibility, especially on major upgrades. Confirm the installed Next.js supports the selected TypeScript compiler. Keep generated runtime and Docker Node versions aligned; the Dockerfile checks the actual versions after pnpm installation.

Resolve exact Debian slim Node and PostgreSQL image tags with real registry digests. Retain the template's Debian/standalone design. Check the PostgreSQL major's data-volume layout before changing its major (the supplied configuration uses the PostgreSQL 18 layout). Resolve real full commit SHAs for Actions; never invent hashes. Keep an explicit supported Ubuntu runner version.

If release information or compatibility cannot be verified, report that fact rather than silently treating template versions as current. Do not weaken the age/trust settings to force a resolution. For an upstream migration, adapt the configuration and verify it while preserving the agreed behavior.

## Version file

`configure.py` reads a JSON object with the following fields. Version strings use exact `major.minor.patch` without a `v` prefix. The installer must verify release age, trust, compatibility and hash provenance; the script validates format and basic consistency only.

| Field | Value |
| --- | --- |
| `node`, `pnpm` | Selected runtime and package-manager versions |
| `nodeImage` | `node:<same-node-version>-trixie-slim@sha256:<verified-digest>` |
| `postgresImage` | `postgres:<selected-version>-trixie@sha256:<verified-digest>` |
| `aquaRegistry`, `lefthook`, `pinact` | Selected official registry/tool versions |
| `checkout`, `pnpmAction` | Verified 40-character commit SHAs for actions/checkout and pnpm/action-setup |
| `dependencies` | Exact npm versions keyed by package name, as listed below |
| `devDependencies` | Exact npm versions keyed by package name, as listed below |

## create-next-app

After verifying the current flags, run the following with the selected generator version and target:

```sh
pnpm create next-app@<verified-version> <target> \
  --ts --app --src-dir --biome --react-compiler \
  --no-tailwind --import-alias '@/*' --empty --use-pnpm \
  --skip-install --disable-git --agents-md
```

Do not use `--yes` to replace these explicit choices. Inspect any new prompts/options. This workflow intentionally generates AGENTS.md and does not install dependencies before the pnpm security configuration is in place.

## Configuration invariants

- package.json: private ESM project; exact packageManager; caret Node runtime with download; no publish version; Next scripts plus lint, typecheck, tests.
- TypeScript: bundler resolution and Next's browser settings; strict, noUncheckedIndexedAccess, exactOptionalPropertyTypes, verbatimModuleSyntax, skipLibCheck; broad include plus Next generated types; allowArbitraryExtensions for messages; no separate CLI build tsconfig.
- Biome: Next/React Domains, recommended preset, space indentation, Git ignore integration, import organization, production-to-test import restriction. Check aliases when extending restrictions. Keep schema URL matched to installed Biome.
- pnpm: engineStrict, strictDepBuilds, blockExoticSubdeps, minimumReleaseAge=10080, minimumReleaseAgeStrict=true, minimumReleaseAgeIgnoreMissingTime=false, trustPolicy=no-downgrade, trustLockfile=false. No default age/trust exceptions.
- Mantine: core CSS, ColorSchemeScript, mantineHtmlProps, provider and matching light defaults; CSS Modules and preset/simple-vars PostCSS. Keep layout a Server Component. No speculative theme wrapper or experimental import optimization.
- next-intl: Japanese request configuration, no locale routes/proxy, generated declarations, global message typing; full lowerCamelCase keys and the name `translate` with no namespace arguments. Do not add an arbitrary timezone.
- Forms: Controller, fieldState.error, Zod input/output types, useWatch, schema factories receiving translated strings. Install the dependencies; create actual forms only for requested behavior.
- Environment: Next loads root .env; server-only Zod getter, public module only when needed; empty example until real values exist; no global secret validation during module import.
- Tests: Node Vitest with explicit imports, nearby `*.test.ts`, passWithNoTests; resolve `@/` consistently with TypeScript. No UI test stack.
- Compose: PostgreSQL, loopback port, named volume, healthcheck, shm_size; preserve local-only example credentials. Next runs outside Compose in development.
- Docker: single dependency install with a locked cache mount, Corepack/pnpm bootstrap, standalone output, built-in node user, writable .next for standard caches, root-owned copied static/public assets. Use the allowlist .dockerignore and exclude generated message declarations and .env files. Do not require production secrets to build the empty application.
- CI: one check job, read-only permissions, no persisted checkout credentials, pinned Actions/runner, timeout, cancellation of outdated runs, frozen install, lint/typecheck/test/build. pnpm manages Node; no redundant setup-node step in this pnpm 12 design.
- Hooks: aqua-managed Lefthook runs lint and typecheck; tests/build belong in CI. Preserve the generated Next.js AGENTS.md block and append project rules. CLAUDE.md references AGENTS.md.
