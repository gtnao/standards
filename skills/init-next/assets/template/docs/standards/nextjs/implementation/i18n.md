# 翻訳の実装方針

[next-intlの導入](../setup/i18n.md)を前提に、文言と呼び出し方を揃える。

## キーの分類と命名

`messages/ja.json`に文言を定義する。キーは各階層ともlowerCamelCaseにする。
画面固有の文言は`pages.<ページ名>`、モデルの項目名は`models.<モデル名>`、共通の入力検証メッセージは`validation`にまとめる。
呼び出しでは常に`pages.home.greeting`のような完全なキーを使う。

```json
{
  "pages": {
    "home": {
      "title": "ホーム",
      "greeting": "こんにちは、{name}さん"
    }
  },
  "models": {
    "user": {
      "name": "名前"
    }
  }
}
```

## 翻訳の呼び出し

非同期Server Componentでは次のように使う。

```tsx
import { getTranslations } from "next-intl/server";

export default async function Page() {
  const translate = await getTranslations();
  return <h1>{translate("pages.home.greeting", { name: "太郎" })}</h1>;
}
```

Client Componentでは次のように使う。`useTranslations`は非asyncのServer Componentでも利用できる。

```tsx
const translate = useTranslations();
translate("pages.home.greeting", { name: "太郎" });
```

翻訳関数の変数名は`translate`に統一し、`t`などへの短縮は禁止する。
`getTranslations`・`useTranslations`に名前空間を指定することも禁止する。
呼び出し側に完全なキーを残すことで、翻訳処理と特定の文言の使用箇所をgrepで検索できるようにする。

翻訳は表示側で行い、[Baseのusecases・domain](../../base/directory-structure.md)にnext-intlへの依存を持ち込まない。

フォームの検証エラーは[React Hook Formの方針](react-hook-form.md#i18nとuseformの接続)に従い、翻訳済みの文言をZodへ渡す。
